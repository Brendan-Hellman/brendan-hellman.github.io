SOFTWARE / CASE STUDY 10

Universal scientific-camera GUI

Implemented / documented

A camera-agnostic imaging application that shares experiment sequencing, display, saving, and analysis across multiple camera backends. Camera-specific SDK behavior is isolated behind a common plugin interface.

PythonPyQt5Scientific imagingPlugin architectureHDF5

My contribution

  • Organized each camera plugin into a driver, acquisition wrapper, and settings panel.
  • Kept TCP sequencing, HDF5 saving, Gaussian fitting, atom-number estimation, and scan plotting in the shared workflow.

Deliverables

  • PyQt5 application and camera plugin packages
  • Dummy, Alvium, Andor ZL41 Wave, and Pixelfly interfaces
  • Architecture and plugin-extension documentation

Recorded outcome

The documented wrapper contract uses prepare_sequence(), grab_frame(), and stop_sequence(). New camera folders with hardware configuration files are discovered by the launcher.

3 methodsShared acquisition contract
4 backendsIncluding the dummy camera

Status & scope

The presence of a camera plugin does not establish that every hardware model was tested.

Credit & context

Scientific-camera SDKs and vendor drivers remain vendor components; the case study focuses on the shared application and integration architecture.
