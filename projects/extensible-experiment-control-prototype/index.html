SOFTWARE / CASE STUDY 12

Extensible experiment-control prototype

Simulation prototype

A newer control-system foundation that discovers devices from manifests and runs validated action configurations through a GUI-independent orchestrator. The included signal generator is a simulator used to develop the extension pattern.

PythonJSON schemaState machinesPlugin discoverySimulation

My contribution

  • Defined device manifests and a common adapter lifecycle so the GUI can create device tabs from metadata.
  • Implemented configuration validation, save/load, run records, stop handling, and explicit orchestration states.

Deliverables

  • Python desktop prototype and Windows launcher
  • JSON schemas, example sequence, tests, and plugin-authoring guide
  • 23-page main guide in the source archive

Recorded outcome

The source provides a complete simulation-first path for adding a device plugin, validating an action configuration, and recording a run without physical hardware.

JSONDevice and action schemas
SimulatorIncluded demonstration device

Status & scope

The README explicitly identifies a simulation-first skeleton. Real-hardware control and deterministic timing are not implemented by the included demonstration device.
